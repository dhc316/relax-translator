# 轻松翻译 0.4 更新说明

## 后台式不等距堆叠

按最新参考图 `references/feedback-0.4/recents-stack.jpg` 调整：按用户指定方向使用左侧完整卡片在前覆盖，当前卡片居中，右侧卡片密集收拢在后。卡片本身不被压缩成窄条；可见宽度来自其他卡片的遮挡及屏幕边界。左侧前景卡片略大，右侧背景卡片略小，固定左高右低的图层顺序贯穿整个滑动过程。

为保证输入可用，静止时左卡只覆盖当前卡约 12dp 的边缘，比 0.3.1 更少；当前卡盖住右卡。输入和按钮保留安全边距；点击实际露出的邻卡切换，左右边界与多卡片切换仍可用。卡片数量改为紧凑页码，避免预设多时指示点挤占标题。

## 两个并行模型请求

A 请求仅要求翻译结果，B 请求要求翻译及全部启用的注音、词汇、纠错、评价和建议。使用当前配置的同一模型、相同的原文、图片及不可变上下文快照，两个 HTTP 请求同时发起。

A 成功立即显示和保存译文，可复制，并显示补充解析的进度。B 成功后更新同一条历史记录，用 B 的译文和读音一起作为完整结果，避免独立请求措辞不同导致注音与译文不匹配。B 先返回时直接显示完整结果并停止不再需要的 A；晚到的 A 不覆盖完整结果。

单个分支失败不会取消另一个分支。B 失败时保留 A 的译文；两次都失败才显示翻译失败。取消和删除操作同时停止相关请求，防止晚到的回复重新生成被删除记录。快速结果已经保存后，即使进程结束也可继续查看，重新打开时将未完成的解析标记为中断。

每次真实翻译会产生两个接口请求；测试连接仍只有一个简短请求。本地演示模拟快速译文及稍后出现的完整解析，不调用外部服务。

## 验证

新增 9 项核心测试，覆盖并行启动、A 先返回、B 先返回、任一分支失败、双方失败、取消、图片与上下文一致及中断后的保存恢复。新增 2 项 Android 流程验证快速译文在 B 被阻塞时已经显示、同一条记录补全、取消保留译文和删除后不回生。原有模型、图片、键盘、预设隔离、注音排序及历史流程继续回归。
