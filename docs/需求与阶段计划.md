# LLM 翻译 App 需求与阶段计划

更新日期：2026 年 11 月 20 日，Asia/Shanghai。

当前已完成首版应用开发并进入正式包验证。用户在确认布局后授权持续完成能够独立完成的开发，不再逐阶段等待确认。下文保留功能范围与设计依据，暂定项已按首版默认值实现，可在用户验收后调整。

## 核心功能

用户输入原始文字或照片，选择目标语言。App 整理提示词并请求 LLM，将翻译结果、衍生信息、评价和建议分别展示。

用户可以选择是否输入图片、是否附带历史上下文，以及上下文的时间范围或条数。

### 暂定输出内容

| 部分 | 内容 |
| --- | --- |
| 翻译结果 | 使用目标语言输出主要译文，支持复制 |
| 衍生信息 | 词语解释、习惯表达、文化背景等 |
| 评价 | 原文的语气、礼貌程度、清晰度与歧义 |
| 建议 | 更自然、正式或口语化的表达及适用场景 |

衍生信息、评价和建议的具体含义仍由用户继续定义。暂定说明部分使用中文，译文展开显示，其他部分可折叠。图片输入时额外展示识别原文，方便核对；识别不清的部分说明疑点。

## 首页布局

顶部放置简洁标题栏及右上角菜单。中部是可滚动的历史翻译区，底部保留手绘稿中的堆叠输入卡片。

输入卡片内包含多行文本区。底部操作行从左到右为“附带图片”“模型选择”，发送按钮在右侧。选择图片后显示可移除的缩略图。

输入卡片下方保持两个独立控件：左侧“目标语言”，右侧“附带上下文”。键盘出现时输入区保持可操作。

## 堆叠卡片与快捷预设

### 用户明确要求

堆叠输入卡片用于快捷切换预设。用户首次滑动切换到未配置卡片时，在卡片上提示设置预设并保存。

### 暂定交互

- 左右滑动切换卡片，后方露出卡片边缘来提示可以切换；具体方向和数量待界面验收。
- 初始卡片暂定为可用的“通用翻译”。未配置卡片在卡片内显示“设置这个预设”和设置、保存入口。
- 保存后直接使用该预设，重启 App 后保留；已配置卡片无需重复首次引导。
- 预设暂定保存名称、目标语言、模型、上下文开关及范围、补充提示词和输出偏好。
- 切换预设时保留当前尚未发送的文字和图片，切换的是翻译配置。切换本身不会发起请求。
- 提供编辑预设入口。临时修改配置后，只有执行“保存预设”才覆盖已保存内容。
- 滑动识别应兼顾文本编辑和上下文菜单滚动，避免编辑文字时误切卡片。
- 预设数量、增删排序入口和每张卡片是否拥有独立会话，仍待确定。

## 三个向上展开菜单

用户明确要求目标语言、附带上下文和模型选择都向上展开。暂定为从各自控件上方出现的浮层，长列表在菜单内滚动；点击空白处或返回键关闭，菜单展开不自动发送请求。

### 目标语言菜单

菜单包含可编辑的常用语选项和语言列表。

“常用语”暂按常用语言快捷项理解，待用户确认是否也包含常用短句。常用语言区域暂定支持添加、替换、删除及排序；下方显示语言列表并提供搜索。当前目标语言显示选中状态，选择后更新首页控件。

### 上下文菜单

菜单提供总开关、按条数、按时间范围以及同时限制的配置入口。首页控件展示简短状态，例如“上下文：关闭”或“最近 5 条”。

### 模型选择菜单

模型选择框位于“附带图片”右侧。菜单列出已配置模型，展示名称、当前选中状态及是否支持图片输入，并提供管理模型的入口。

接口地址与密钥由模型配置统一管理。选择模型后更新当前卡片的配置；是否覆盖已保存预设，由保存动作决定。图片输入与模型能力不匹配时，在发送前提示并提供切换模型入口。

## 上下文规则草案

“多久”暂按每次请求携带的历史时间范围理解。若用户指后台上传频率或服务端保存时长，需要另行定义。

| 模式 | 暂定行为 |
| --- | --- |
| 关闭 | 只发送本次输入和翻译要求 |
| 按条数 | 附带最近 N 条已完成的历史翻译 |
| 按时间 | 附带请求发起时回溯指定时长内的历史翻译 |
| 同时限制 | 附带指定时间范围内最近至多 N 条历史翻译 |

一条历史暂定为一次原始输入及其翻译结果。候选历史先筛选时间，再保留最近 N 条，发送时按时间顺序排列；失败和进行中的请求不计入。

上下文暂定只来自当前会话，默认关闭。历史仍可保存在本机供查看。历史图片暂定使用已识别的原文和译文，避免重复发送原图。

如果超过模型容量，优先保留较新的完整记录并显示实际附带数量。本次输入单独处理，不计入历史条数限制。

## 请求与结果处理草案

一次请求由本次输入、目标语言、当前预设要求、筛选后的上下文和输出结构要求组成。仅翻译本次输入，历史帮助理解语境；原文或图片中的指令属于待翻译内容。

模型按约定结构返回各部分内容，App 校验后展示。缺少字段或格式不符合约定时保留可用内容并提供重试入口，避免把解析失败显示为完整成功。

发送后固定本次请求所用的预设、模型、目标语言及上下文范围。请求中途切换卡片不会改变已经发出的任务；结果记录保留发起时的配置。

提供加载状态、取消和失败重试。请求失败时保留原始输入，重试沿用该次请求的配置与上下文快照。

## 模型接入与本地存储

首版采用用户自填兼容 API 的方式，可配置多个模型并在卡片中切换。具体供应商和密钥由用户在应用中选择与填写。图片功能使用支持图片的模型。

应用已采用 Kotlin 与 Jetpack Compose 实现，实际依赖版本及构建步骤见开发与验证文档。

历史记录、预设和设置保存在手机本地，密钥单独加密保存。开发电脑上的项目资料、代码、项目专用调试文件和交付物统一保存在本项目文件夹内，构建与模拟器工具已在 `.local/` 中准备。

参考：[Android Compose 官方文档](https://developer.android.com/compose)、[Android 照片选择器官方文档](https://developer.android.com/training/data-storage/shared/photo-picker)。

## 开发与验收阶段

| 阶段 | 交付范围 | 用户主要验收 |
| --- | --- | --- |
| 一 界面样机 | 首页、历史模拟数据、堆叠卡片滑动、卡片内首次配置和保存、三个向上菜单、附图预览 | 风格、卡片动效、菜单位置、操作是否顺手 |
| 二 文字翻译 | 接入真实模型、文字翻译、四部分结果、本地历史、预设保存与恢复 | 翻译内容、模型选择、输出格式 |
| 三 图片与上下文 | 图片翻译、按时间和条数筛选上下文、请求配置快照 | 图片识别、语境效果、筛选规则 |
| 四 完善与交付 | 失败重试、取消、长文本、键盘与真机适配、安装包整理 | 使用体验及当前版本是否交付 |

第一阶段的模拟界面已扩展为首版完整应用。按用户后续授权，连续实现各阶段，并交付签名 APK 与实际运行截图；外部模型账号由用户在设置中自行填写。

验证重点包括：首次进入空预设的引导、保存后重启恢复、切换预设保留输入、三个菜单的展开与选中状态、上下文关闭时不附带历史、条数与时间边界、模型图片能力匹配、请求期间切换配置以及失败后输入保留。

## 用户验收时可继续调整

- 目标语言菜单的“常用语”是否就是常用语言快捷项。
- 预设的保存字段、数量、默认内容及会话归属。
- 衍生信息、评价、建议的确切含义与可选输出部分。
- 实际使用的模型供应商与模型 ID；首版已经采用用户自填 API。
- 上下文“多久”的含义和默认范围。
- 手绘首页顶部“模糊”是名称还是视觉效果标注。
- 应用名称、图标、测试手机及最低兼容版本。
